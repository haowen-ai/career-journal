# 填表任务说明模板

[English](fill-brief.md) | [简体中文](fill-brief.zh-CN.md)

主 Agent 为每个岗位复制一份下面的模板，替换全部 `{{占位符}}`，写到仓库以外的私有临时路径，再交给一个填表子 Agent。填好的任务说明含有个人文件路径，因此不得提交到仓库、写进日志或分享出去。

| 占位符 | 填入内容 |
|---|---|
| `{{company}}` | 公司名，用于标签标题 |
| `{{role}}` | 岗位原名 |
| `{{applicationId}}` | CAREER JOURNAL 中的申请 ID |
| `{{applyUrl}}` | 经 `queue verify` 核实过的官网申请链接 |
| `{{browserTools}}` | 如何加载宿主的浏览器工具，例如用一次工具搜索一次性加载全部浏览器工具 |
| `{{answersPath}}` | `<home>/.career-journal/profile/answers.md` |
| `{{profilePath}}` | `<home>/.career-journal/profile/profile.json` |
| `{{resumePath}}` | 用户为这个岗位选定的那一份简历 |
| `{{resumeTextPath}}` | 可选：这份简历的纯文本副本，用于原样复制 bullet；没有时写 `none` |
| `{{transcriptPath}}` | `materials.transcriptPath`，没有时写 `none` |
| `{{locationOrder}}` | 按顺序列出 `search.locations` 的名称，并写明是否接受远程 |
| `{{exclusions}}` | 用平实语言写出 `search.exclusions` |
| `{{atsTipsPath}}` | 本仓库中 `references/ats-tips.zh-CN.md` 的路径 |
| `{{titleLanguage}}` | 标签标题说明文字使用的语言，例如英文或简体中文 |

---

````markdown
# 填表任务：{{company}} — {{role}}

你只负责在用户自己的浏览器里填写一份求职申请：{{company}} — {{role}}（CAREER JOURNAL ID {{applicationId}}）。动浏览器之前，完整读完本说明和 {{atsTipsPath}}。

浏览器工具：{{browserTools}}

## 你的标签页

- 为 {{applyUrl}} 新开一个标签页，并记下它的 ID。只用这一个标签页，不读取、不复用、不关闭任何别的标签页。
- 网站自己在新标签页中打开申请时，那个新标签页也归你；记下它的 ID。
- 标签页丢失时（扩展掉线、标签组被关），在新标签页中重新打开申请链接：网站保存了草稿就从草稿继续，没有草稿就从头重填。并在报告中说明发生过中断。

## 硬规矩

1. 不点任何写着 Submit*（Submit、Submit Application、Submit Profile 等）的按钮，即使它看起来只是中间步骤；也不点其他任何会把申请发出去的按钮。停在它前面，由用户自己点。
2. 不替用户登录、注册账号，不输入密码或验证码，也不做或绕过 CAPTCHA。
3. 不勾同意、声明、认证或仲裁条款，不代签名：不手写签名，也不输入姓名或日期作为电子签名。
4. 不写作文：cover letter、why us、动机和补充问答都属于用户本人。只整理用户自己说的话。
5. 成绩单只在表单把成绩单设为必填项时上传；不放进简历、可选或“其他附件”位置。
6. 只上传一份简历，即用户选定的那份：`materials.resumePath`，或者用户为该岗位明确指定的版本。不换成其他版本。
7. 工作描述每条一行，行首加“• ”。
8. 不把个人资料写进仓库。资料、答案表、简历、成绩单、截图、填好的任务说明和填表报告只放在用户的数据目录或私有临时目录。

Next、Continue、Save and Continue 这类中间按钮可以点。宿主的权限系统拦下某次点击时，不要设法绕过：停下来，报告用户需要点哪个框或按钮。

## 填表前

- **是否已投过？** 查看网站的候选人后台或“已申请”提示。用户已经投过这个岗位时，停下并报告“已投过”。
- **地点。** 表单要求选择地点或办公室时，按这个顺序选：{{locationOrder}}。岗位只在这些地点以外开放时不要填写，停下并报告岗位提供的地点。
- **资格。** 岗位原文或表单排除了用户的学历层次、毕业时间或工作身份，或者符合 {{exclusions}} 时，停下并报告原文。

## 事实

- 完整读取 {{answersPath}} 和 {{profilePath}}，它们是唯一的事实来源。备注可以是任何语言；按表单语言填入答案表给出的准确值。
- 工作描述：原样复制简历 bullet（{{resumeTextPath}}），每条一行，行首加“• ”。
- 网站解析简历并预填学历或工作经历时，逐项与事实核对并改正。
- 需要具体日期的字段：答案表没有给出日期时，用当月 1 日。
- 自愿披露（性别、族裔、退伍军人、残障等）：完全按答案表填写，包括用户选择的“不愿透露”。答案表没有时留空并报告，不得猜测。
- 可选的营销、短信、人才库或 AI 处理授权：保持不勾选，或选择不同意的选项。
- 不编造任何内容：薪资数字、考试分数、语言水平、日期、推荐人或联系方式。答案表没有覆盖的必填题留空，把标题设为 `❓`，并报告原题、选项和是否必填。
- 作文、cover letter 和 why us 类问题保持空白。报告题目原文、是否必填和字数限制。简短的事实题（例如列出会用的编程语言）可以按答案表填写。

## 文件

- 简历：用宿主的文件上传工具和文件输入框的引用，上传 {{resumePath}} 这一份，不上传其他版本。
- 成绩单（{{transcriptPath}}）：只在表单把成绩单设为必填项时上传，不放进简历、可选或“其他附件”位置。
- 每次上传后，确认页面显示了文件名。

## 填值方法

按 {{atsTipsPath}} 中的通用方法和各招聘系统要点操作。简单说：隐藏标签页里优先用 JavaScript 而不是键盘鼠标；用原生 value setter 再触发 input 和 change 事件；选择 React 下拉框前先找到当前 fiber；用 MessageChannel 代替 `setTimeout` 等待；每个值填完都读回确认；不得刷新填了一半的页面。

## 需要用户的情况

网站需要用户本人操作时（登录、账号、密码、邮件验证码、CAPTCHA、同意、签名）：

1. 在不做这一步的前提下尽量往前走，例如点 Apply 走到登录页。
2. 用{{titleLanguage}}把标签标题设为 `🔑待登录 {{company}}`（登录、账号、密码或验证码）、`🤖待验证 {{company}}`（CAPTCHA）、`❓待回答 {{company}}`（答案表没有的必填题）或 `👆待点击 {{company}}`（同意、签名，或写着 Submit* 的中间步骤按钮），并用 `setInterval` 保持。
3. 立即报告用户具体要做什么。

## 完成

到达最终确认页、点任何提交按钮之前，把标题设为 `✅待提交 {{company}}`，并用 `setInterval` 保持，因为单页应用会重置标题。

简要报告：

- 标签页 ID 和停下的页面；
- 用户需要点的每一个框或按钮；
- 每个留空或不确定的字段：原题、选项、是否必填、字数限制；
- 实际上传的简历文件，以及是否上传了成绩单、原因是什么；
- 任何你不确定的值（不应该有任何猜测的值）。
````
